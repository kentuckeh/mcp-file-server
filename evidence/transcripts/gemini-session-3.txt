│ Waterfall Model                                                          │
│                                                                          │
│ > Reviewed in Session 2. See INDEX.md for the full list.                 │
│                                                                          │
│ Definition                                                               │
│  - A linear-sequential software development lifecycle model where each   │
│    development phase must be completed before the subsequent phase       │
│    begins.                                                               │
│                                                                          │
│ When to Use                                                              │
│  - Best suited for projects with well-defined, stable requirements,      │
│    mature technology, and minimal likelihood of mid-project changes.     │
│                                                                          │
│ Pros                                                                     │
│  - Simple, structured, and easy to understand and manage with clear      │
│    milestones and deliverables.                                          │
│  - High level of documentation discipline and predictable scheduling for │
│    fixed-scope projects.                                                 │
│                                                                          │
│ Cons                                                                     │
│  - Inflexible to requirement changes once development is underway.       │
│  - Working software is produced late in the development cycle,           │
│    increasing late-stage integration and delivery risk.                  │
│                                                                          │
│                                                                          │
│ ✓  read_file (file-server MCP Server) read_file(path: notes/process-mod… │
│                                                                          │
│ Incremental Model                                                        │
│                                                                          │
│ > Reviewed in Session 2. See INDEX.md for the full list.                 │
│                                                                          │
│ Definition                                                               │
│  - A software development model where the product is designed,           │
│    implemented, and tested in successive, modular increments with each   │
│    release adding functional capability.                                 │
│                                                                          │
│ When to Use                                                              │
│  - Best suited when core system requirements are defined upfront but     │
│    secondary features can evolve, or when early market entry is          │
│    critical.                                                             │
│                                                                          │
│ Pros                                                                     │
│  - Delivers functional software early and frequently, providing          │
│    immediate operational value to users.                                 │
│  - Easier to test, debug, and manage technical risk through smaller,     │
│    modular stages.                                                       │
│                                                                          │
│ Cons                                                                     │
│  - Demands strong architectural foresight and clean interfaces to avoid  │
│    integration friction between increments.                              │
│  - Total development cost may exceed initial estimates if increment      │
│    scopes expand iteratively.                                            │
│                                                                          │
│                                                                          │

│  - Best suited for dynamic projects with uncertain or fast-evolving      │

│                                                                          │

│                                                                          │
│ Cons                                                                     │
│  - Challenging to forecast overall project duration, budget, and final   │
│    scope in early project stages.                                        │
│  - Requires high stakeholder involvement, experienced self-organizing    │
│    teams, and disciplined communication.                                 │
